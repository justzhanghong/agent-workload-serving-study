# Coding / Work场景的多轮Workload研究索引

核对日期：2026-10-20。核心23项研究/工具/硬件方法，场景背景4项；不是Agent框架、题库或能力综述。

## 选取与核验原则

优先原论文与作者材料，纳入直接分析多轮轨迹、上下文/KV、工具等待、任务调度、跨层资源或观测的方法，并补充P/D交接与decode硬件评估。仅凭名称包含Agent不构成纳入理由；普通聊天只作对照。不是穷尽式系统综述，不混排论文性能，不把上游收益当成本地复现。

方法与测量对象来自原工作，边界是本文用于避免误读的归纳。版本化链接固定本次所引稿件；年份取首次发布或所引会议版本。图R1～R3为负载与测量方法归纳，不复制原图。DCP是官方工程材料，HeteroPanacea是模拟研究，LLMCompass是通用硬件方法，不能统一称为Agent轨迹论文。

## 多轮负载特征与生产轨迹

| 研究/工具 | 考察的负载与方法 | 测量什么 | 适用边界 |
|---|---|---|---|
| [AgentSysBench](https://arxiv.org/abs/2608.15127) [1] | 统一工作负载/服务栈说明与多组件测量，并补充生产轨迹 | 端到端耗时、状态、资源与控制面行为 | 受控执行与生产观察回答互补问题，不互相替代 |
| [TraceLab](https://arxiv.org/abs/2606.30560v2) [8]，v2 | 真实Claude Code/Codex日志归一为session—用户请求—模型step，保留时间、token与工具元数据 | 自主循环长度、上下文增长、append/new输入、工具长尾、跨用户间隙缓存复用 | 开发者样本与特定提供商；append包含缓存未命中的旧历史，不等于全新信息 |
| [Agentic Coding in the Wild](https://arxiv.org/abs/2608.00101v1) [9]，v1 | GitHub Copilot生产轨迹，区分用户轮次与轮内工具驱动循环 | 轮内/跨轮命中、工具间隙与用户空闲、模型切换及压缩边界 | 生产观测存在模型、路由和用户混杂；跨轮命中下降不自动等于HBM容量不足 |
| [Agentic AI Workload Characteristics](https://arxiv.org/abs/2605.26297v2) [10]，v2 | 贯通Agent侧与推理服务的端到端跟踪，比较模型与推理配置 | 重复模型进入、缓存后的prefill/decode、工具读写阶段与持续KV状态 | 缓存后decode占优是所测条件的观察，不是所有Agent部署的定律 |

## 轮间KV状态与缓存管理

| 研究/工具 | 考察的负载与方法 | 测量什么 | 适用边界 |
|---|---|---|---|
| [CacheWise](https://arxiv.org/abs/2606.16824v1) [11]，v1 | 真实coding轨迹分析，结合前缀感知调度与工具元数据预测复用 | KV驱逐/重算、命中与整session完成时间 | 收益依赖负载与资源；较高命中率本身不保证更好整题时间 |
| [Continuum](https://arxiv.org/abs/2511.02230v7) [12]，v7 | 按恢复成本与排队影响选择性设置KV驻留TTL，结合程序级调度 | 轮间等待、恢复开销、job完成时间、预测不准时的稳健性 | 不能无限保留所有等待会话；需在复用与挤占活跃请求间权衡 |
| [InferCept](https://arxiv.org/abs/2402.01869) [22] | 围绕外部交互暂停选择保留、换出或重算上下文 | 状态占用与恢复/服务效率权衡 | 策略收益依赖等待时长、链路和资源条件 |
| [TokenCake](https://arxiv.org/abs/2510.18586v5) [18]，v5 | 工具等待时卸载/预测换入KV，按图结构和运行状态安排内存 | 空闲缓存挤占、关键路径代理被驱逐、整工作流耗时 | 用于有依赖的多Agent工作流；四个独立客户端并发不等于其执行拓扑 |

## 工作流调度与跨层接口

| 研究/工具 | 考察的负载与方法 | 测量什么 | 适用边界 |
|---|---|---|---|
| [Parrot](https://arxiv.org/abs/2405.19888) [21] | Semantic Variable暴露请求之间的数据流依赖 | 应用端到端服务表现 | 需要应用信息，不等价于只调单请求batch大小 |
| [Autellix](https://arxiv.org/abs/2502.13965v1) [13]，v1 | 将程序身份及已完成调用的服务信息送入调度器 | 累计排队、队首阻塞、程序完成延迟和吞吐 | 程序感知调度不同于只调单请求batch；非所有流程都预先已知 |
| [HEAR](https://arxiv.org/abs/2610.06597v1) [14]，v1 | 双向交换harness的工作流/生命周期意图与engine的队列/KV状态 | 缓存协同、运行模式、端到端延迟及质量约束 | 协议不是固定优化策略；研究任务中的收益不等于已在本地接入 |
| [Cortex](https://arxiv.org/abs/2510.14126v1) [17]，v1 | 原型按工作流阶段隔离资源池并定制调度 | 阶段间计算/内存干扰、KV利用和吞吐可预测性 | 原型与阶段分解有适用边界，不是已证明的通用生产最佳方案 |

## 全栈资源观测与服务基础

| 研究/工具 | 考察的负载与方法 | 测量什么 | 适用边界 |
|---|---|---|---|
| [CPU-Centric Perspective](https://arxiv.org/abs/2511.00739v3) [15]，v3 | 跨两类硬件刻画CPU/GPU执行，研究重叠微批与混合负载调度 | 工具/编排CPU瓶颈、重叠、异构请求队首阻塞 | 包括相邻Agent任务，不能把其CPU瓶颈直接套到每个coding/办公任务 |
| [Architectural Implications](https://arxiv.org/abs/2608.04458v1) [16]，v1 | Azure生产观察与受控框架实验结合，按执行结构和资源角色分析 | CPU—GPU碎片化、突发、局部性、角色化资源与状态换入 | 负载受框架、任务、工具和模型组成共同影响，利用率相关不替代干预 |
| [AgentSight](https://arxiv.org/abs/2508.02736) [19] | 在边界关联LLM通信与eBPF内核事件 | 跨进程语义—动作观测与诊断 | 观测工具不是任务正确性的验收器 |
| [SGLang](https://arxiv.org/abs/2312.07104) [20] | 结构化程序前端与RadixAttention前缀复用运行时 | 多调用程序的执行效率 | 前缀复用不等于跨会话事实记忆正确性 |
| [PagedAttention](https://arxiv.org/abs/2309.06180) [5] | 分页式KV块管理及共享 | 显存管理效率与推理吞吐 | 缓存管理机制，不是完整Agent任务基准 |
| [AgentX Harness](https://github.com/SemiAnalysisAI/agentx-harness) [3] | 按轨迹长度和前缀共享结构回放模型请求 | 推理延迟、吞吐及缓存行为 | 不自动恢复工具语义、真实等待或任务质量 |

## P/D交接与decode硬件设计方法

| 研究/工具 | 考察的负载与方法 | 测量什么 | 适用边界 |
|---|---|---|---|
| [vLLM DCP](https://vllm.ai/blog/2026-08-07-decode-context-parallelism) [29] | 固定模型/硬件/负载，比较TP与按序列切分KV的decode context parallelism | 长上下文KV占用、并发、吞吐—交互速度与collective通信 | 官方工程测量，非同行评审论文；KV复制取决于模型和并行实现，不能直接套到V4.1或目标ASIC |
| [HeteroPanacea](https://arxiv.org/abs/2608.03741v1) [30]，v1 | 以分阶段roofline/互连模型搜索P/D与Attention/FFN异构配置及精度 | 受功耗或成本约束的配置收益与模型架构敏感性 | 自定义NPU结果是模拟；组件校验不等于端到端调度已验证。固定中心长度的合成负载不能代替真实轮间轨迹 |
| [PPD](https://arxiv.org/abs/2603.13358v2) [27]，v2 | 测量完整/增量prefill对decode的干扰，动态选择后续轮次的P端或D端执行 | 后续轮次TTFT、TPOT干扰与KV传输拥塞 | 其canonical基线假设单向P到D交接；不能推广为所有PD协议均重算完整历史，也不能直接推定ASIC算力配比 |
| [AMPD](https://arxiv.org/abs/2602.14516v2) [28]，v2 | 联合离线代价建模、部署规划与在线增量prefill路由/重排 | TTFT/ITL约束、历史KV访问、增量KV返回与资源配置 | 远端P必要时先读取D的历史KV；仅回传增量不等于无历史传输。本地暂停decode是其实现行为，非所有硬件必然如此 |
| [LLMCompass](https://github.com/PrincetonUniversity/LLMCompass) [31] | 联合硬件模型、算子映射/调度搜索与面积成本模型进行设计空间评估 | 算子/模型延迟、计算与内存配置的成本—性能取舍 | 通用LLM硬件评估方法，不是Agent轨迹研究；目标MLA/稀疏/MoE算子和动态服务行为须另行扩展、校准 |

## 场景背景（不作为Workload分析主线）

| 研究/工具 | 考察的负载与方法 | 测量什么 | 适用边界 |
|---|---|---|---|

## 使用说明

前四组为Workload/系统主线，第五组补充P/D交接与decode硬件方法；最后一组只解释Coding与企业工作的场景来源，不展开能力评测。AgentX是回放工具，papers.cool是AgentSysBench论文的检索入口，不重复计为另一篇研究。

本报告统一术语：session可含多个用户需求，每个需求含多次模型API和工具动作。不同论文的request/turn/step含义必须先对齐再比较。

报告第2.10节对应文献机制与设计问题，第3.6节给出E1～E4待执行方案；新文献未作为本地已复现性能或ASIC测量。
